❯ What are we trying to accomplish? 

⏺ Based on the CLAUDE.md file, Inexora is an Oracle Database driver and Ecto adapter for Elixir applications. Here's what we're building:

  Core Goal

  Create a way for Elixir developers to connect to Oracle databases (12c+) using the standard Ecto ORM interface.

  Technical Approach

  1. NIF-based driver - Use Erlang NIFs (Native Implemented Functions) to interface with ODPI-C, Oracle's official C library for database connectivity
  2. Ecto Adapter - Implement the adapter layer so Elixir apps can use Oracle with Ecto just like they would PostgreSQL or SQLite

  Key Inspirations

  - Postgrex - The gold-standard Elixir database driver
  - Exqlite - A similar NIF-based approach for SQLite that we're modeling after

  Current Status

  The project has just started - nothing is completed yet. The roadmap includes:
  - Driver initialization and context support
  - Database connections
  - SQL statement execution
  - Result set handling
  - Data type support (VARCHAR2, NUMBER, DATE/TIMESTAMP, etc.)
  - Ecto adapter functions

  Why This Approach?

  Rather than implementing Oracle's TNS wire protocol from scratch (complex and hard to maintain), leveraging ODPI-C keeps the driver aligned with what Oracle officially supports while avoiding duplication of effort.

     Inexora: Minimal NIF Setup Implementation Plan

     Goal

     Set up the minimal NIF infrastructure that can:
     1. Compile ODPI-C via elixir_make
     2. Load the NIF into the BEAM
     3. Call odpi_version() to verify the binding works (no Oracle client
     required)

     Files to Create/Modify

     1. Update mix.exs

     Add dependencies and configure elixir_make compiler:
     - {:elixir_make, "~> 0.8", runtime: false}
     - {:db_connection, "~> 2.6"}
     - {:decimal, "~> 2.0"}
     - Add compilers: [:elixir_make] ++ Mix.compilers()

     2. Add ODPI-C Git Submodule

     git submodule add https://github.com/oracle/odpi.git c_src/odpi

     3. Create Makefile

     Cross-platform build configuration for the NIF:
     - Detect platform (macOS/Linux)
     - Include Erlang NIF headers and ODPI-C headers
     - Compile c_src/inexora_nif.c + c_src/odpi/embed/dpi.c
     - Output to priv/inexora_nif.so

     4. Create c_src/inexora_nif.c

     NIF implementation with:
     - dpiContext resource type with destructor
     - odpi_version/0 - returns ODPI-C compile-time version
     - context_create/0 - creates ODPI-C context
     - context_destroy/1 - destroys context
     - get_client_version/1 - gets Oracle client version

     5. Create lib/inexora/nif.ex

     Elixir NIF module:
     - @on_load :load_nif callback
     - Function stubs that delegate to NIF
     - Type specs and documentation

     6. Update lib/inexora.ex

     Delegate odpi_version/0 to Inexora.Nif

     7. Update .gitignore

     Add NIF artifact patterns (priv/*.so, c_src/*.o)

     8. Create test/inexora/nif_test.exs

     Tests for NIF functions:
     - odpi_version/0 should always work
     - Context tests tagged :oracle_client (excluded by default)

     9. Update test/test_helper.exs

     Exclude :oracle_client tagged tests by default

     Verification Steps

     # 1. Initialize submodule
     git submodule update --init --recursive

     # 2. Get dependencies
     mix deps.get

     # 3. Compile (triggers NIF build)
     mix compile

     # 4. Run tests
     mix test

     # 5. Manual verification in iex
     iex -S mix
     iex> Inexora.Nif.odpi_version()
     {:ok, {5, 6, 4}}  # or similar version tuple

     The odpi_version/0 call proves the NIF compiled and loaded correctly,
     without needing Oracle Instant Client installed.

     Key Implementation Notes

     1. ODPI-C embed approach: Use c_src/odpi/embed/dpi.c single-file
     compilation
     2. Resource cleanup: dpiContext wrapped in Erlang resource with
     destructor
     3. Error handling: ODPI-C errors converted to {:error, {code, 
     function, message}}
     4. No Oracle client needed: odpi_version() works without Oracle
     Instant Client
